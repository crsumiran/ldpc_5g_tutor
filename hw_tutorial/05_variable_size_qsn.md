# 05 · Variable Z: The QSN Trick

> **Goal:** Build one 384-lane network that correctly rotates a vector of **any** length Z ≤ 384. This is the minimum requirement for a 5G decoder.
>
> * **RTL:** `rtl/rot_qsn.v`
> * **Python Model:** `model/rotators.py::rotl_qsn`

## 1. The Problem, Concretely

A 5G decoder must rotate vectors of length Z, but the hardware has a fixed number of lanes N. When Z < N, only lanes 0 … Z − 1 hold data, and the rotation must wrap at lane Z, not at lane N. Take N = 8 lanes, Z = 5, s = 2, and data `[A B C D E . . .]`:

```
want                       C D E A B . . .
N-lane barrel rotator      C D E . . . A B     ✗  wraps at lane 8, not lane 5
```

The barrel rotator from Chapter 04 gets this partly right:

* **Lanes 0–2 are correct:** They only needed elements that did not wrap.
* **Lanes 3–4 are wrong:** The values that should have wrapped to them went to lanes 6–7 instead.

5G has 51 lifting sizes, so building 51 rotators and muxing between them is clearly not an option.

## 2. Ideas That Do Not Scale

Before getting to the QSN, it helps to see why the obvious alternatives fail:

| Idea | Why not |
|---|---|
| One rotator per Z, select the right output | 51 × the area |
| Per-lane Z:1 mux driven by `(i + s) mod Z` | That is a crossbar again (N² cost), plus a modulo per lane |
| Pad Z up to N and fill unused lanes | Changes the code; the circulant is Z×Z, not N×N |

## 3. The QSN Idea: Two Shifters and a Merge

### Step 1: Split the Output Lanes

The key observation is that a rotation of a Z-element vector treats two groups of output lanes differently. Split the output lanes into the ones that **do not wrap** and the ones that **do**:

* **Lane `i < Z − s` (no wrap):** It takes `x[i + s]`, a plain **left shift** by s.
* **Lane `i ≥ Z − s` (wraps):** It takes `x[i + s − Z]`, a plain **right shift** by `Z − s`.

**Neither group needs a rotator: each one is served by an ordinary non-circular shifter.** So we compute both shifts and pick per lane:

```
left  = din << s           (non-circular, zero fill)
right = din >> (Z − s)     (non-circular, zero fill)
dout[i] = (i < Z − s) ? left[i] : right[i]          for i < Z
```

### Step 2: A Worked Example

With N = 8, Z = 5, s = 2, the threshold is Z − s = 3:

```
din                 A B C D E 0 0 0
left  = din << 2    C D E 0 0 0 0 0
right = din >> 3    0 0 0 A B C D E
mask  (i < 3)       1 1 1 0 0 0 0 0
dout                C D E A B . . .   ✓
```

The final mux column is called the **merge network**. Its select is a **thermometer code** of `Z − s`: ones in the lanes below the threshold, zeros above.

### How to Read the QSN Diagram

* **Each shifter is a barrel rotator without the wrap-around wires:** Compare it with the Chapter 04 figure. Where the barrel had a dashed wire back to the top of the bus, the shifters have a constant `0` input. The left shifter moves values toward lane 0, so its constant zeros are at the bottom lanes; the right shifter moves values the other way, so its zeros are at the top.
* **Each shifter's selects are just the bits of its amount:** The left shifter shifts by `s = 2 = 010₂`, so only stage 1 is active. The right shifter shifts by `Z − s = 3 = 011₂`, so stages 0 and 1 are active. The only extra control is the one subtractor that computes `Z − s`.
* **Each shifter gets part of the answer right:** The left shifter's output lanes 0–2 (C D E) are correct, because those values did not need to wrap. The right shifter's output lanes 3–4 (A B) are correct, because those are the values that wrap.
* **The merge column picks the correct lanes from each:** Here it is drawn with select 1 meaning "take the right shifter", so its selects read `0 0 0 1 1`. That is the thermometer code of `Z − s = 3`, the inverse of the `i < Z − s` mask above. Lanes 5–7 are outside the vector, so the RTL forces them to 0.
* **The cost is visible:** There are 2 × 24 shifter muxes plus 8 merge muxes, compared with 24 for the fixed-size barrel rotator: roughly double, as Section 5 says.

## 4. The RTL

`rtl/rot_qsn.v` has three parts: the two shift amounts, the two non-circular shifters, and the merge column.

```verilog
wire [ZW-1:0] lshift = shift;          // left shifter amount
wire [ZW-1:0] rshift = z - shift;      // right shifter amount: one subtractor

// two log-depth NON-circular shifters, same structure as rot_barrel but zero-filling
//   ls[k+1][i] = lshift[k] ? ls[k][i + 2^k] (or 0) : ls[k][i]
//   rs[k+1][i] = rshift[k] ? rs[k][i - 2^k] (or 0) : rs[k][i]

// merge: one 2:1 mux per lane, select = (i < rshift)
assign dout[i*W +: W] = !valid   ? 0 :
                        use_left ? ls[ZW][i*W +: W] : rs[ZW][i*W +: W];
```

The testbench runs every one of the 51 lifting sizes with every legal shift: 4,479 cases, all lanes compared.

## 5. Cost and the Control Path

| Part | 2:1 muxes per bit (N = 384) | Control |
|---|---|---|
| Left shifter | ≈ 384 × 9 | shift bits directly |
| Right shifter | ≈ 384 × 9 | `Z − s`: one 9-bit subtractor |
| Merge | 384 | 384 compare-with-constant (thermometer) |
| **Total** | ≈ 7,300 | small |

A non-circular shifter is slightly cheaper than a rotator: lanes near the edge get a constant 0 instead of a mux. The QSN paper counts this exactly.

Compared with a fixed-size barrel rotator, **QSN roughly doubles the datapath to gain full Z flexibility**, while control stays cheap.

**Timing tip:** The subtractor `Z − s` sits in front of the right shifter's selects and the merge thermometer, so it lengthens the critical path. Shift values come from a table anyway, so **precompute `Z − s` and store it next to `s`**. That takes the subtractor out of the datapath cycle.

## 6. A Third Idea: Replicate the Data

There is another way to avoid handling the wrap at all. If lanes `Z … 2Z−1` held a **copy** of the vector, a single left *shift* by s would already give `x[(i + s) mod Z]` in lanes 0…Z−1, with no wrap to handle.

This works directly only while `2Z − 1 ≤ N`. Above that you need extra lanes or an extra layer. Boutillon & Harb's *Extended Barrel Shifter* (EBS, 2020) builds on an "extra layer + specific initial data positioning" approach in this spirit and reports 42% fewer muxes than the prior best at n = 384. See Chapter 09. Treat this section as intuition only and read the paper for their exact scheme.

## 7. What QSN Still Cannot Do

QSN handles one vector per cycle. At Z = 24 on a 384-lane QSN, 360 lanes carry nothing. Chapter 06 fixes that with Banyan-based networks that split into independent sub-rotators.

### Solutions to Selected Exercises

> **Solution to Exercise 1:**
> Z − s = 1.
> * **left** = din << 5 = `F 0 0 0 0 0 0 0`
> * **right** = din >> 1 = `0 A B C D E F 0`
> * **mask** = lane 0 only
> * **dout** = `F A B C D E` ✓ (x[(i+5) mod 6])

> **Solution to Exercise 2:**
> Lane i = Z − s should take x[Z], which wraps to x[0]; that value is `right[i]`. The left shifter at that lane holds x[Z], which is outside the vector (a lane ≥ Z: zero or garbage).
