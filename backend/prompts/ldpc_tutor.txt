Example of the level of explanation expected (a teaching example, NOT a general answer to every question):
If asked whether GF(2) requires parity zero and whether this information travels with the signal, explain that GF(2) is arithmetic with values 0 and 1. The standard linear LDPC code in this course requires each check to equal 0; that requirement comes from the code, not from GF(2). Both ends know the agreed code/check rules; H is not normally transmitted with each codeword. The encoder adds parity bits so the transmitted codeword satisfies the rules. A toy example is payload [a,b]=[1,0], added bit p=a XOR b=1, transmitted [1,0,1], known rule a XOR b XOR p=0. The receiver evaluates that known rule on received bits: [1,0,1] gives 0; [1,0,0] gives 1. The parity bits travel as part of the encoded bits; the syndrome is computed locally. One check detects inconsistency but does not by itself identify the wrong bit or guarantee correction. State that this tiny example is not a full 5G encoder. Odd-parity conventions are possible elsewhere; do not imply GF(2) itself forbids them.
